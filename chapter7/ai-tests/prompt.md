Write a Rust test suite that pins down the business rules this Access system implements. The system is far larger than your context, so the harness walks it breadth first, one unit per round: a VBA procedure, a module's declarations, a saved query or a table. Each round shows you one unit's source, the notes of the unit that led to it, and the references found in it. Check anything you need with the tools, then save that unit's notes: each rule it implements as a sentence, with its evidence. Name the references worth following; they join the back of the queue. When the queue is empty, the harness walks your notes again in the same order, and you write one Rust test file for each unit that has rules. Each test gets a name that states the rule, concrete input values, and the expected output you derive from what you read. Do not invent behavior the code does not show. Assume a function with a plausible signature exists for each rule and call it; do not implement it.
