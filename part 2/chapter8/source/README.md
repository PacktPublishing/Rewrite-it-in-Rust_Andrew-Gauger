# Cairn Systems: Orders & CRM Database

A Microsoft Access database for Cairn Systems. It tracks customers, contacts, quotes, sales orders, payments, sales activities, phone messages and returns (RMAs), and sends hardware orders to the manufacturer. It prints quotes, receipts, invoices, RMA summaries and monthly commission statements.

The whole database is generated by three VBA modules. You can rebuild it from scratch at any time.

Some parts are **built badly on purpose**, the way a ten-year-old Access file really is, so the book's replacement has real problems to solve. See [Built this way on purpose](#built-this-way-on-purpose).

## Requirements

- Windows with Microsoft Access 2010 or later (Microsoft 365 works)
- Macros enabled for the database. If Access shows a yellow **Security Warning** bar, click **Enable Content**. The forms' buttons won't work until you do.

## Using the database

| `admin` | `admin` | Administrator |

Admins can add and change accounts on the **Users** screen. **Sign Out** on the main menu returns to the sign-in form. Passwords are stored as plain text (see [Built this way on purpose](#built-this-way-on-purpose)), so never reuse a real password here.

### Main menu

- **Records:** Customers, Quotes, Sales Orders, Products, Sales Reps, Company Info, Returns (RMAs), and Users (admins only)
- **Take Phone Message / Log Activity:** opens a blank entry form
- **Month-end:** Orders, Sales by Rep, Sales by Product, Cash Received, Quote Pipeline and Open Receivables. Each asks for a month: type any date in that month, e.g. `9/1/2026`.
- **Commission Statements:** prints commission statements for a month (see [Reports](#reports))
- **Qualified Leads:** prospects that meet the sales team's definition of a qualified lead
- **RMA Summary:** prints the returns opened in a month, grouped by route
- **Dashboard lists:** open phone messages, and follow-ups due in the next 7 days. Double-click a row to open it.

### Day-to-day tasks

**Add a customer.** Open **Customers** and click the new-record button (▶*) at the bottom. Contacts, activities, quotes and orders for the customer appear in the tabs at the bottom.

**Write a quote.** On the customer, click **New Quote**. The quote number, sales rep, primary contact and tax rate fill in automatically. Tax is 0% for tax-exempt customers. Add line items in the grid; picking a product fills in its price. The totals update as you go.

**Turn a quote into an order.** On the quote, click **Create Order from Quote**. This copies the quote and its line items into a new sales order and marks the quote *Accepted*.

**Record a payment.** On the sales order, type the payment into the **Payments** grid. *Paid* and *Balance Due* update automatically.

**Take a phone message.** Click **Take Phone Message** on the main menu. When the call has been returned, open the message and click **Mark Returned**.

**Log a return.** Open **Returns (RMAs)** and add a record. The RMA number fills in automatically. Pick the customer, order, product and reason; the **Route** box shows where the return goes, from the saved query `qryRMARouting`.

**Order hardware from the manufacturer.** On the sales order, click **Send to Manufacturer**. It sends the order's hardware lines to the manufacturer's order API, and the manufacturer's order number appears in **Mfr Order**. Access waits, frozen, until the manufacturer answers. If it doesn't answer, Access offers **Retry**. To try this without a real manufacturer, start `MockManufacturer\Start-MockManufacturer.ps1` first.

**Find a record.** Every main form has a **Go to:** box at the top right.

### Reports

| Report | How to print it | What it shows |
|---|---|---|
| Quote | **Print Quote** on the Quotes form | Letterhead, customer, line items, totals, terms, acceptance signature line |
| Receipt | Click a payment in the Payments grid on a sales order, then **Print Receipt** | The payment, the order's items, and the amount paid and balance as of that payment |
| Commission statements | **Commission Statements** on the main menu | One page per sales rep: their orders, net sales, commission owed and signature lines. A final page totals all reps. |
| Invoice | **Print Invoice** on the Sales Orders form | One page for a window envelope: address, line items, totals, payments, amount due, and a tear-off remittance stub. **Its line-item box holds 6 lines** and anything after that isn't printed, though the totals include it. |
| RMA summary | **RMA Summary** on the main menu | Returns opened in a month, grouped by route |

Each report opens in Print Preview. From there you can print it, or use **PDF or XPS** on the ribbon to save a PDF.

**How commission is calculated:** the rep's commission rate × net sales. Net sales means the order's line items after discounts, before tax and shipping. Every order dated in the month counts unless it is *Cancelled*, whether or not the customer has paid. Each statement shows how much of those orders is still unpaid. You set each rep's rate on the **Sales Reps** form.

## Built this way on purpose

These parts copy the way such files are really built. They are the problems the replacement has to solve, so **don't fix them in this database**.

| What | Where | The problem |
|---|---|---|
| Sign-in | `Users` table, `LoginCheck` (CairnForms) | Passwords are stored and compared as plain text. The SQL is built by pasting in what was typed, so the password `x' OR '1'='1` signs in as the first active user. In the history database, three reps who left still have active accounts, and the shared `sales` and `temp` logins still work. |
| RMA routing | `qryRMARouting` | One saved query of eight nested `IIf` calls. The **Bench Test** branch can never be reached: an earlier branch already catches everything it would. A return whose order isn't in the file gets a blank *days in service*, every comparison becomes Null, and it falls through to **Customer Pays Repair**. |
| Returns table | `RMAs` | No relationships to Orders, Products or Customers, so it can hold order numbers that don't exist |
| Qualified leads | `qryQualifiedLeads` | A rule someone decided once: a Prospect with an open quote of $5,000+, or two touches in 90 days in one of three industries, and a Director or Manager on file. An existing customer buying more never counts, and neither does a small business whose contact is the owner. |
| Manufacturer orders | `SendManufacturerOrder` (CairnForms) | The JSON request is pasted together as a string, so a quote mark in a name breaks it. The call is synchronous, so Access freezes until the manufacturer answers. Nothing in the request identifies a repeat, so a retry orders the hardware twice. If the connection drops on a reused keep-alive connection, Windows resends it on its own and nobody is asked: see `MockManufacturer\README.md`. |
| Invoice | `rptInvoice` | Laid out for a window envelope, with a fixed line-item box that holds 6 lines. Longer orders print without their extra lines, while the totals still include them. |

## Before going live

1. **Company Info:** replace the placeholder address, phone, email and website. All three reports use this. You can also set the default tax rate, standard quote terms and the receipt footer here.
2. **Sales Reps and Products:** enter your real reps (with commission rates) and products.
3. **Clear the sample data:** press Alt+F11, click inside `ClearSampleData` in the **CairnBuild** module and press F5. This deletes the sample customers, contacts, quotes, orders, payments, activities, messages, returns, manufacturer calls, sales reps and their sign-ins. It keeps Company Info, Products and the `admin` sign-in. **It cannot be undone**, so make a copy of the database first.

## Numbering

- Quotes are numbered `Q-YYYY-####` and sales orders `SO-YYYY-####`. Numbering restarts at 0001 each year.
- Receipts use the payment's ID, e.g. `00002`.

## Building from scratch

Use this to create a fresh database, for example after major changes to the scripts.

1. In Access, create a **Blank database** (e.g. `CairnSystems.accdb`) and close the empty *Table1* without saving.
2. Press **Alt+F11** to open the VBA editor.
3. Go to **File > Import File** and import `CairnBuild.bas`, `CairnForms.bas` and `CairnReports.bas`.
4. Run these three procedures in order. For each one, click inside it and press **F5**:
   1. `BuildCairnDatabase` in **CairnBuild**: tables (including Users, RMAs and ManufacturerOrders), relationships, sample data, queries
   2. `BuildCairnForms` in **CairnForms**: forms and the main menu; the sign-in form is set as the startup form
   3. `BuildCairnReports` in **CairnReports**: reports
5. Close and reopen the database.

If a step fails, a message shows the exact statement that broke.

### Rebuilding parts of an existing database

Each of these is safe to run again on a database that already has data. Your data is not touched.

| Procedure | Module | Recreates |
|---|---|---|
| `RebuildQueries` | CairnBuild | All saved queries |
| `RepairTextDefaults` | CairnBuild | Text field defaults (e.g. a new quote's *Draft* status). Also fixes any rows saved with stray quote marks, such as `'Draft'`. |
| `AddOperationsTables` | CairnBuild | Adds the Users, RMAs and ManufacturerOrders tables (with sample sign-ins and returns), the manufacturer address in Company Info, and their queries. Tables that already exist are left alone. Run `BuildCairnForms` and `BuildCairnReports` afterwards to get the sign-in, RMA and Users forms and the new reports. |
| `BuildCairnForms` | CairnForms | All forms |
| `BuildCairnReports` | CairnReports | All reports |

**Updating a module.** In the VBA editor, right-click the old module, choose **Remove**, and answer **No** to the export prompt. Then import the new `.bas` file. Importing without removing the old module first gives you a duplicate (e.g. *CairnForms1*) and "ambiguous name" errors.

Any manual changes you make to the forms or reports in Design View are overwritten when you rebuild them. To keep a change permanently, make it in the `.bas` file instead.

## History database

`CairnSystems_History.accdb` is a copy of the database filled with ten years of **fictional** history. Use it for demos, training and trying out reports. Never enter real business in it.

| Year | Orders | Net sales |
|---|---|---|
| 2016 (year 1) | 926 | $18.0M |
| 2017 | 990 | $19.5M |
| 2018 | 996 | $20.9M |
| 2019 | 1,082 | $22.6M |
| 2020 | 1,091 | $24.2M |
| 2021 | 1,297 | $25.7M |
| 2022 | 1,342 | $27.6M |
| 2023 | 1,388 | $30.0M |
| 2024 | 1,445 | $32.2M |
| 2025 (year 10) | 1,505 | $35.0M |
| 2026 to Oct 10 | 1,210 | $28.0M |

*Net sales* means order lines after discounts, before tax and shipping, excluding cancelled orders. This is the same figure the commission statements use.

**What's in it:**
- 1,000 customers in 8 industries: some long-standing, some lost along the way, and about 200 prospects that never bought.
- 14 sales reps. Some have left, and their accounts passed to the remaining reps.
- 21 products, with launches, discontinued models and prices about 3% lower for each year back.
- 19,000 quotes, with about 53% won and the rest declined or expired.
- 13,500 orders, 17,000 payments, 68,000 CRM activities and 4,600 phone messages.
- Recent orders are realistically still open, in production or awaiting payment. There is about $7.7M in open receivables.
- 17 sign-ins, with plain-text passwords. Three belong to reps who left and still work; there are also shared `sales` and `temp` logins.
- 772 returns (RMAs), 29 of them for orders that aren't in the file.
- 9,054 calls to the manufacturer's order API since it went live in March 2019. On 246 orders the first attempt failed. Some of those timed out *after* the manufacturer had taken the order, so the retry ordered the hardware a second time, and Access only recorded one manufacturer number. You can see the gaps in the MFR- numbers.

**Messy data, added on purpose** (for the extraction chapter to find):
- 14 customers entered a second time under a slightly different name (`Inc.`, `, LLC`, all capitals, a transposed letter, a double space). The newer record has the customer's latest order or two.
- A retired status: 31 orders from 2017–2018 still say **Back Order**, and 12 quotes from 2018 say **On Hold**.
- 9 quotes saved as `'Draft'` and 4 customers as `'Prospect'`, with the quote marks: the bug `RepairTextDefaults` fixes.
- 162 orphaned quote lines. The QuoteLines relationship was removed and put back unenforced, then 38 declined 2019 quotes were deleted and their lines stayed behind. That also leaves gaps in the 2019 quote numbers.
- Pricing arrangements typed into customer Notes as codes, each rep their own way: `[GOV]`, `gov pricing`, `[DIST-15]`, `dist 15%`, `KEY ACCT`, `net 60 ok - per Priya` and so on.

The sales figures in the table above are unchanged by all of this.

**To regenerate it:**
1. Copy `CairnSystems1.accdb` to a new file.
2. Open the copy and import `CairnHistory.bas`.
3. Run `GenerateHistory`. It takes a few minutes. It ends by adding the sign-ins, returns, manufacturer calls and messy data.

It refuses to run on a database that already has more than 50 orders. It uses a fixed random seed, so the same starting database gives the same history.

The sales history is generated up to the day you run it, so a new copy won't match the figures above exactly. To add just the sign-ins, returns, manufacturer calls and messy data to an existing history database, run `AddOperationsTables` (CairnBuild), then `AddOperationsHistory` (CairnHistory). That part has its own random seed and doesn't change the sales history.

## How it's put together

### Tables

| Table | Holds |
|---|---|
| `CompanyInfo` | One row: your letterhead, default tax rate, quote terms, receipt footer |
| `SalesReps` | Reps and their commission rates |
| `Customers` | Customer companies, billing and shipping addresses, assigned rep |
| `Contacts` | People at each customer. One can be marked *Primary*. |
| `Products` | SKU, price, cost, category, lead time |
| `Quotes` / `QuoteLines` | Quotes and their line items |
| `Orders` / `OrderLines` | Sales orders and their line items, with serial numbers |
| `Payments` | Payments received against orders |
| `Activities` | CRM log of calls, meetings, emails and notes, with follow-up dates |
| `PhoneMessages` | "While you were out" messages |
| `Users` | Sign-in accounts (plain-text passwords) |
| `RMAs` | Returns: customer, order, product, serial number, reason, status |
| `ManufacturerOrders` | Every call to the manufacturer's order API: request, answer or error, manufacturer order number |

Relationships enforce referential integrity. Deleting a quote or order deletes its line items. Deleting a customer deletes its contacts and activities. `RMAs` has no relationships, and in the history database the QuoteLines relationship is not enforced.

### Key queries

| Query | Used for |
|---|---|
| `qryQuoteTotals`, `qryOrderTotals`, `qryOrderBalances` | Subtotal, tax, total, paid and balance for each quote or order |
| `qryQuotePrint`, `qryReceiptPrint` | Record sources for the quote and receipt reports |
| `qryCommissionDetail` | Record source for the commission statements |
| `qryMonthEnd_*`, `qryOpenReceivables` | Month-end queries on the main menu |
| `qryOpenPhoneMessages`, `qryFollowUpsDue` | Dashboard lists on the main menu |
| `qryInvoicePrint` | Record source for the invoice |
| `qryRMARouting` | Every return with its route; record source for the RMA summary |
| `qryQualifiedLeads` | The qualified-leads list on the main menu |
| `qryManufacturerLog` | Every call to the manufacturer, newest first |

### Code

The forms and reports have no code of their own. Their buttons and events call public functions in the **CairnForms** and **CairnReports** modules. **Keep both modules in the database**, or the buttons stop working.
